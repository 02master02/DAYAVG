# 任务目标

## 用户原始需求

用户显式启用了 `vibe-coding-workflow` 技能，希望当前仓库后续开发遵循该工作流。

## AI 的任务目标

本轮先完成项目工作流初始化，而不是开始业务代码开发：
- 建立 `docs/`、`src/`、`tests/`、`outputs/` 基础结构
- 创建必需的项目文档
- 记录当前默认假设与后续接手方式

## 输入

| 输入项 | 来源 | 格式 | 示例 | 是否必需 |
|---|---|---|---|---|
| 用户指令 | 对话 | 文本 | `[$vibe-coding-workflow](...)` | 是 |
| 当前仓库状态 | 本地工作区 | Git 仓库 | 仅有 `.git/` | 是 |

## 输出

| 输出项 | 格式 | 保存地址 | 用途 |
|---|---|---|---|
| 工作流文档 | Markdown | `docs/` | 记录目标、计划、进度、交接信息 |
| 项目骨架 | 目录与占位文件 | `src/`, `tests/`, `outputs/` | 为后续开发提供规范结构 |
| 项目说明 | Markdown | `README.md` | 说明当前仓库用途 |

## 约束条件

- 先写文档，再写生产代码
- 不覆盖或删除已有用户文件
- 当前没有明确业务需求，因此只做安全的工作流初始化
- 所有后续输出默认放在 `outputs/`

## 默认假设

- 项目名称暂以仓库名 `DayAvg` 为准
- 本轮目标仅为“初始化工作流”，不擅自创建具体产品功能
- 依赖列表暂为空，待真实功能需求出现后再补充

## 验收标准

- [x] 已创建并填写必需文档
- [x] 已建立基础目录结构
- [x] 已记录后续继续开发所需的 handoff 信息
- [x] 未声称完成任何未执行的业务代码或测试结果
