# 任务目标

## 用户原始需求
用户希望做一个可在局域网访问的 Python Web 应用，带前端页面。输入物品价格和购买时间后，系统计算从购买日至今天为止的日均持有成本，并保存历史记录。

后续需求又扩展为：

- 前端改成更像移动端资产仪表盘的卡片式页面
- 支持修改已有物品的价格和购买日期
- 使用用户提供的 PNG 图标并自动分类
- 支持把不再使用的产品标记为“已退役”
- 为退役物品补充手动退役日期和退役备注

## 当前任务目标
当前版本为 DayAvg V1.4，目标是：

- 保持 `Flask + Jinja2 + SQLite` 架构
- 支持新增、查看、修改已有记录
- 支持真实 PNG 图标自动分类展示
- 支持把物品标记为退役并冻结后续时间计算
- 支持手动设置退役日期和退役备注
- 保持正常物品按今天实时更新，退役物品按退役日期冻结
- 保持局域网可访问
- 用自动化测试覆盖核心流程

## 输入

| 输入项 | 来源 | 格式 | 示例 | 是否必填 |
|---|---|---|---|---|
| 物品名称 | 新增表单 | 文本 | `iPhone 15` | 是 |
| 购买价格 | 新增/修改表单 | 正数，最多两位小数 | `5999.00` | 是 |
| 购买日期 | 新增/修改表单 | `YYYY-MM-DD` | `2026-05-01` | 是 |
| 记录 ID | 历史卡片 | 整数 | `1` | 修改或退役时需要 |
| 退役日期 | 退役设置表单 | `YYYY-MM-DD` | `2026-05-18` | 设置退役时必填 |
| 退役备注 | 退役设置表单 | 最多 200 字文本 | `屏幕坏了，已封存` | 否 |

## 输出

| 输出项 | 形式 | 位置 | 用途 |
|---|---|---|---|
| 首页仪表盘 | HTML | `GET /` | 展示录入表单、汇总指标和资产卡片 |
| 历史记录 | SQLite | `outputs/dayavg.db` | 本地持久化保存 |
| 自动化测试 | Python | `tests/` | 验证新增、修改、退役和恢复流程 |
| 项目文档 | Markdown | `docs/` | 记录目标、计划、使用方式和交接信息 |

## 约束条件

- 当前版本不做删除、登录、图表、分页或筛选
- 按自然日计算持有天数，最小值为 `1`
- 不允许未来购买日期
- 不允许 `0` 或负数价格
- 金额用 `Decimal` 计算，数据库按“分”存储
- 当前仅允许修改价格和购买日期，不修改物品名称
- 退役日期不能早于购买日期，也不能晚于今天
- 退役后冻结在退役日期对应的持有天数和日均持有成本

## 默认假设

- “每天的价格”按“日均持有成本”解释，而不是折旧曲线
- 页面继续采用单页服务端渲染，不拆前后端
- 历史记录按创建时间倒序展示
- 正常物品始终按“今天”动态更新
- 退役物品始终按 `retired_on` 冻结

## 验收标准

- [x] 首页可访问，包含录入表单、汇总指标和历史列表
- [x] 可以新增物品并立即看到日均持有成本
- [x] 可以修改已有物品的价格和购买日期
- [x] 可以为物品设置退役日期和退役备注
- [x] 正常物品会随当前日期推进而继续变化
- [x] 退役物品会冻结在指定退役日期
- [x] 可以恢复使用并重新回到动态更新状态
- [x] 自动化测试覆盖新增、修改、退役设置、恢复和页面渲染流程
