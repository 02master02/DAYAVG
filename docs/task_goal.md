# 任务目标

## 用户原始需求

用户希望做一个可在局域网访问的 Python Web 应用，带前端页面。输入物品价格和购买时间后，系统计算从购买日至今天为止的日均持有成本，并保存历史记录。

此前已完成的功能包括：

- 仪表盘式首页展示
- 资产新增
- 基于 PNG 图标的分类展示
- `localStorage` 快照持久化
- JSON 导入导出

## 本轮任务目标

本轮只完善“资产操作”相关能力，不改动整体页面结构，不新增图表、搜索和筛选：

- 每条资产支持编辑：名称、分类、购买价格、购买日期、备注
- 每条资产支持删除，删除前需要二次确认
- 完善“退役设置”：退役日期、退役原因、二手卖出价格、退役备注
- 已退役资产的持有天数冻结在退役日期，使用中资产继续按今天增长
- 已退役资产的日均成本按“购买价格 - 二手卖出价格”重新计算
- 顶部“使用中 / 已退役”数量随编辑、删除、退役和恢复正确更新
- 保持当前 Flask + Jinja2 + SQLite 技术栈，不引入前端构建工具
- 尽量维持当前 UI，不做大改版

## 当前技术栈确认

- 后端：`Flask`
- 模板：`Jinja2`
- 数据存储：`SQLite`
- 前端：原生 HTML + CSS + 少量原生 JavaScript
- 包管理：`requirements.txt`
- 当前仓库不存在 `package.json`

## 输入

| 输入项 | 来源 | 格式 | 示例 | 是否必填 |
|---|---|---|---|---|
| 物品名称 | 新增/修改表单 | 文本 | `iPhone 15` | 是 |
| 物品分类 | 新增/修改表单 | 枚举文本 | `手机` | 是 |
| 购买价格 | 新增/修改表单 | 正数，最多两位小数 | `5999.00` | 是 |
| 购买日期 | 新增/修改表单 | `YYYY-MM-DD` | `2026-05-01` | 是 |
| 资产备注 | 新增/修改表单 | 最多 300 字文本 | `国补购入，主力机` | 否 |
| 退役日期 | 退役设置表单 | `YYYY-MM-DD` | `2026-05-18` | 退役时必填 |
| 退役原因 | 退役设置表单 | 最多 120 字文本 | `升级换代` | 退役时必填 |
| 二手卖出价格 | 退役设置表单 | 非负数，最多两位小数 | `2500.00` | 否 |
| 退役备注 | 退役设置表单 | 最多 300 字文本 | `同城卖出，配件齐全` | 否 |
| 导入 JSON 文件 | 导入表单 | UTF-8 JSON 文件 | `dayavg-export.json` | 导入时必填 |

## 输出

| 输出项 | 形式 | 位置 | 用途 |
|---|---|---|---|
| 首页仪表盘 | HTML | `GET /` | 展示当前资产列表 |
| 本地资产快照 | JSON 字符串 | `localStorage` | 浏览器端持久化副本 |
| 导出文件 | JSON | 浏览器下载 | 备份与迁移资产数据 |
| 导入结果 | 页面提示 + 列表更新 | `POST /items/import` | 恢复已导出的资产列表 |
| 历史记录 | SQLite | `outputs/dayavg.db` | 服务端持久化数据 |

## 约束条件

- 不重构当前卡片式页面和服务端渲染结构
- 不大改页面布局和视觉风格
- 导入失败时，现有数据库内容必须保持不变
- 导出 JSON 必须能被当前版本重新导入
- `localStorage` 写入失败时不能让页面崩溃
- 保持当前测试框架为 Python `unittest`

## 默认假设

- 现有 SQLite 仍然是服务端真实数据源
- `localStorage` 作为浏览器端镜像备份和前端持久化副本
- JSON 导入采用“整批替换当前资产列表”的行为
- 导入数据只接受本项目导出的结构化 JSON
- 分类改为可手动指定，页面展示优先使用用户选择的分类
- 二手卖出价格为空时按 `0` 处理
- 二手卖出价格不能高于购买价格

## 验收标准

- [ ] 使用中资产会继续增长持有天数
- [ ] 已退役资产的持有天数固定在退役日期
- [ ] 设置二手卖出价格后，退役资产日均价格会下降
- [ ] 编辑、删除、退役、恢复后刷新页面数据仍然正确
- [ ] 顶部“使用中 / 已退役”数量正确更新
- [ ] 导出的 JSON 仍能被当前版本重新导入
